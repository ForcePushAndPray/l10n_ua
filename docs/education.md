# Заклади освіти

← [Назад до головної](../README.md)

Облік для українських освітніх установ (ЗДО, ЗЗСО, ліцеї, ПТУ, ЗВО I–IV рівнів): контингент, навчальні групи та роки, стипендії, дитяче харчування, каркас обміну з ЄДЕБО.

Легенда статусів: ✅ Стабільний · 🟢 Робочий · 🟡 Бета · 📦 Збірка

| Модуль | Версія | Статус | Призначення |
|--------|--------|--------|-------------|
| `l10n_ua_education` | 19.0.1.0.0 | 📦 | Збірка стеку освіти (base + scholarship + edebo) |
| `l10n_ua_education_base` | 19.0.1.0.0 | 🟢 | База: типи закладів, навчальні роки, групи, контингент |
| `l10n_ua_education_scholarship` | 19.0.1.0.0 | 🟢 | Стипендії: типи, відомості виплати, ПДФО/ВЗ, КЕКВ 2720 |
| `l10n_ua_education_edebo` | 19.0.1.0.0 | 🟢 | Каркас імпорту/експорту контингенту (CSV/XLSX) |
| `l10n_ua_education_edebo_xml` | 19.0.1.0.0 | 🟢 | Плагін: XML-парсер для `_parse_custom()` (МОН) |
| `l10n_ua_education_meals` | 19.0.1.0.0 | 🟡 | Дитяче харчування: меню, техкартки, відвідуваність |

> Напрям у стадії бета-розробки. Реальні тести є в base, scholarship, edebo та edebo_xml; модуль meals тестів не має.

---

## Огляд

- **base** — фундамент: тип закладу на компанії, навчальні роки, групи/класи/курси, облік контингенту з life-cycle.
- **scholarship** — типи стипендій, відомості виплати з рядками, оподаткування, привʼязка до бюджетного обліку (`l10n_ua_budget_base`).
- **edebo / edebo_xml** — інфраструктура обміну з ЄДЕБО: базовий CSV/XLSX-каркас + XML-плагін як точка розширення.
- **meals** — облік харчування у ЗДО/школах: меню, технологічні картки страв, відвідуваність для розрахунку порцій.

---

## `l10n_ua_education` 📦

Мета-модуль (umbrella). `data: []`, залежить від `l10n_ua_education_base`, `l10n_ua_education_scholarship`, `l10n_ua_education_edebo`. Ставиться для розгортання повного стеку одним кроком. `application: True`. Для повного бюджетного циклу окремо ставиться `l10n_ua_budget`.

## `l10n_ua_education_base` 🟢

Залежності: `base`, `hr`, `l10n_ua_account_base`.

**Моделі:**
- `l10n_ua.education.academic.year` — навчальний рік («2025/2026»), обчислюваний `year_end`, прапорець активності (лише один активний рік), контроль коректності дат.
- `l10n_ua.education.group` — група / клас / курс; рівень і профіль, прив'язка до навчального року (успадковує активний за замовчуванням), лічильник членів.
- `l10n_ua.education.contingent.member` — учень/студент/вихованець; `mail.thread` + `mail.activity.mixin`, обчислюваний `display_name`. Life-cycle: `applicant → enrolled → studying → graduated / expelled / transferred` (заборонено «перестрибувати» стани). Прив'язка до `res.partner`, опційно до `hr.employee`. Номер студента унікальний у межах компанії.
- `res.company` (_inherit) — поля типу закладу освіти (ЗДО, ШНЗ, ПТУ, ЗВО I–IV рівнів).

**Дані:** передзаповнені навчальні роки (`data/l10n_ua_education_academic_year_data.xml`).

**Тести:** `tests/test_education_base.py` — 11 тестів (обчислення `year_end`, валідація дат, єдиний активний рік, дефолт року групи, повний і «зламаний» life-cycle контингенту, відрахування з абітурієнта, невідповідність року групи, поля компанії, унікальність номера студента, лічильник членів групи).

## `l10n_ua_education_scholarship` 🟢

Залежності: `l10n_ua_education_base`, `l10n_ua_budget_base`.

**Моделі:**
- `l10n_ua.scholarship.type` — типи стипендій (академічна, соціальна, президентська, іменна, стипендія Верховної Ради, обласна); ознака оподаткування, КЕКВ за замовчуванням.
- `l10n_ua.scholarship.payment` — відомість виплати; `mail.thread`, послідовність номера, state machine `draft → approved → paid → cancelled`, дефолт КЕКВ 2720 з типу, вибір фонду, опційно КПКВК. Інтеграція з `l10n_ua_budget_treasury` (контроль ліміту при проведенні, якщо встановлено).
- `l10n_ua.scholarship.payment.line` — рядок по члену контингенту; розрахунок ПДФО/ВЗ для оподатковуваних стипендій, без дублювання члена в межах однієї відомості, заборона від'ємної суми, домен лише на активних студентів.

**Дані:** типи стипендій (`data/l10n_ua_scholarship_type_data.xml`), послідовність номерів.

**Тести:** `tests/test_scholarship.py` — 11 тестів (створення з послідовністю, дефолт КЕКВ, life-cycle, заборона затвердження порожньої/скасування оплаченої, без дублів члена, від'ємна сума, домен активних студентів, нульовий податок для неоподатковуваних, розрахунок ПДФО/ВЗ, сумісність оплати без журналу).

## `l10n_ua_education_edebo` 🟢

Залежність: `l10n_ua_education_base`. Каркас інтеграції з Єдиною державною електронною базою освіти.

**Візарди:**
- `l10n_ua.edebo.import` — імпорт студентів/учнів з CSV/XLSX; режим «сухого прогону» (dry-run) та реального створення членів контингенту. Точка розширення `_parse_custom()` для власних форматів обміну.
- `l10n_ua.edebo.export` — експорт контингенту в CSV (лише активні члени).

> ⚠️ Специфікація форматів ЄДЕБО закрита й регулярно оновлюється — модуль надає лише інфраструктуру. Конкретні формати підключаються плагінами (див. `l10n_ua_education_edebo_xml`).

**Тести:** `tests/test_edebo.py` — 6 тестів (dry-run та реальний CSV-імпорт, помилка на некоректному CSV, вимога плагіна для `custom`-формату, експорт лише активних, помилка на порожньому експорті).

## `l10n_ua_education_edebo_xml` 🟢

Залежність: `l10n_ua_education_edebo`. Плагін, що переозначає `_parse_custom()` для `file_format = 'custom'` та парсить XML.

**Особливості:**
- Парсинг за припущеною структурою `<edebo><students><student>…`; підтримка синонімів тегів (`TAG_SYNONYMS`) через `_edebo_xml_extract_persons()` — переозначується в дочірньому модулі під реальний контракт МОН.
- Експорт у XML ще не реалізовано (потребує цифрового підпису — окремий PR).

> ⚠️ Реальний формат ЄДЕБО варіюється — вбудована структура є робочим прикладом.

**Тести:** `tests/test_edebo_xml.py` — 5 тестів (базовий XML-імпорт, альтернативні назви тегів, реальне створення членів, помилки на некоректному та порожньому XML).

## `l10n_ua_education_meals` 🟡

Залежність: `l10n_ua_education_base`. Облік дитячого харчування для ЗДО і шкіл.

**Моделі:**
- `l10n_ua.meal.recipe` + `l10n_ua.meal.recipe.ingredient` — технологічні картки страв з інгредієнтами.
- `l10n_ua.meal.menu` + `l10n_ua.meal.menu.line` — щоденне меню; вікова група, вид прийому їжі (сніданок/обід/полуденок/вечеря), обчислення сумарних КБЖВ (калорії, білки, жири, вуглеводи), стан `draft → approved`.
- `l10n_ua.meal.attendance` — відвідуваність по групі/класу: присутні/відсутні, кількість порцій за прийомами їжі (для розрахунку фактичної кількості).

**Обмеження поточного стану (чесно):**
- **Немає тестів** — модуль не покритий автотестами.
- **Модель `l10n_ua.meal.norm` (вікові добові норми) не реалізована** — згадана в описі маніфесту, але відповідного файлу моделі та подання немає.
- **Немає пільгових / безкоштовних категорій харчування** — облік ведеться лише за загальною кількістю порцій і видом прийому їжі; розподіл на платні / пільгові / безкоштовні категорії (діти пільгових категорій за ПКМУ) поки не підтримується. Питання відкрите й потребує окремої доробки.

## Встановлення

```bash
odoo-bin -d <db> -i l10n_ua_education --stop-after-init
```

Для харчування додатково:

```bash
odoo-bin -d <db> -i l10n_ua_education_meals --stop-after-init
```

Для XML-обміну з ЄДЕБО додатково ставиться `l10n_ua_education_edebo_xml`.
