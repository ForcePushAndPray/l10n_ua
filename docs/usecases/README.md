# Use-кейси по доменах + звірка з законодавством

← [Назад до документації](../../README.md)

Нумеровані **use-кейс флоу** (тестові сценарії) по кожному домену, за аналогією з
`HR_UKRAINE.md`: короткий вступ із ролями → флоу через реальні моделі/поля/стани/кнопки
коду → розділ **«Звірка з законодавством»** із чесним переліком прогалин реалізації.

Це специфікації/аудит відповідності — призначені для перевірки повноти реалізації
проти чинного законодавства України, а не маркетинг. Прапорці прогалин (`заглушка`,
`частково`, `не реалізовано`, `орієнтовно`) є навмисними й відображають фактичний стан коду.

## Наскрізні висновки звірки

Систематичні ризики, що повторюються в кількох доменах:

- **Секрети відкритим текстом** — API-токени/паролі (banks, marketplaces, supplier_prices)
  зберігаються без шифрування, попри заяву «encrypted».
- **Відсутність КЕП** для вихідних дій (платіжки, декларації, чеки, підпис договорів через
  `sign_oca` ≠ кваліфікований підпис).
- **Персональні дані** — медичні (medicine) і покупців маркетплейсів (`raw_data`) без
  груп доступу/шифрування/ретеншену/згоди (№2297-VI).
- **Домени-каркаси** з заглушками замість реальних викликів: delivery (усі API перевізників),
  prro (офлайн/Z-звіт), medicine eHealth (dry-run без ЕСОЗ).
- **Незакрита фіскалізація** (№265/95-ВР) — marketplaces не формує ПРРО-чек при онлайн-продажу.
