## l10n_ua_agreement — Договори

Облік договорів з клієнтами: від типізації та підписання до виставлення
рахунків. Призначено для ФОП і підприємств, що надають послуги за договором.
Модуль не створює власну модель — він розширює модель `agreement` (OCA) та
українізує її UI.

### Можливості

- **Розширення моделі `agreement`** з власним станом: Чернетка → На підписанні →
  Підписаний (додатково: Завершений, Скасований)
- **Українізація базових полів** OCA-модуля `agreement` (номер, назва, клієнт,
  тип, шаблон, дати, сфера тощо)
- **Типи договорів** (`agreement.type`) з передзаповненими записами: Послуги,
  Поставка товарів, Підряд, Абонентське обслуговування (усі `domain='sale'`)
- **Електронний підпис** через `sign_oca`: кнопка «Надіслати на підпис» рендерить
  PDF договору, створює `sign.oca.request` і прив'язує його через `record_ref`;
  після повного підписання (`_check_signed`) договір автоматично переходить у
  стан «Підписаний», зберігаються дата підпису, підписаний PDF та ім'я файлу
- **Додаткові угоди** як дочірні договори (`parent_agreement_id` /
  `child_agreement_ids`); ознака `is_amendment` обчислюється автоматично
- **Друковані форми (QWeb PDF)**: «Договір» та «Акт наданих послуг», обидві
  прив'язані до моделі як звіти (binding)
- **Періодичні (абонентські) рахунки** через `contract.contract`: кнопка
  «Створити періодичний договір» створює запис `contract.contract` з
  `agreement_id`
- **Аналітичні поля**: предмет договору (`subject`, Html), валюта, сума договору
  (`amount_total`, Monetary)
- **Smart-кнопки** на формі: кількість запитів на підпис, дод. угод,
  періодичних договорів
- **Звітність**: pivot/graph «Аналіз договорів» (групування за типом і станом)

### Модель та стани

Модель `agreement` (`_inherit`) отримує поле `state`:

| Стан | Значення |
|------|----------|
| `draft` | Чернетка |
| `to_sign` | На підписанні |
| `signed` | Підписаний |
| `expired` | Завершений |
| `cancelled` | Скасований |

Дії стану: `action_confirm` (→ на підпис), `action_draft` (→ чернетка),
`action_cancel` (→ скасований).

```

        └── l10n_ua_agreement
```

### Структура меню

Основне меню «Договори», список та «Налаштування → Типи договорів» надаються
базовим OCA-модулем `agreement`. Модуль додає лише пункт звітності:

```
Договори (OCA)
└── Звітність
    └── Аналіз договорів — pivot/graph (сума за типом і станом)
```

### Потік роботи

1. Створити договір (клієнт, тип, предмет, сума, дати); за потреби скопіювати з
   шаблону (`is_template`, механізм OCA `agreement`)
2. Друк «Договір» (звіт прив'язаний до моделі)
3. «Надіслати на підпис» → створюється `sign.oca.request`, договір → «На
   підписанні»; клієнт підписує
4. Після повного підпису договір автоматично «Підписаний», підписаний PDF та
   дата підпису зберігаються в договорі
5. Для абонентських послуг — «Створити періодичний договір» (`contract.contract`)
6. За фактом надання — друк «Акта наданих послуг»

### Інтеграція з ФОП

Рахунки з договорів (через `agreement_sale` / `contract.contract`) стають
джерелом доходу для `l10n_ua_fop` (книга обліку доходів, 5% ЄП від надходжень).

### Встановлення

```bash
# OCA-залежності (гілка 19.0) agreement, agreement_sale, sign_oca, contract
# мають бути в addons_path
odoo-bin -d <db> -i l10n_ua_agreement --stop-after-init
```
