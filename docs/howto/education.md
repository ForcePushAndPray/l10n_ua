## 0. Застосунок домену

Меню застосунків (сітка ▤ ліворуч угорі) → **Освіта (UA)**. Верхнє меню модуля:

| Пункт | Призначення |
|-------|-------------|
| **Контингент** | Учні / студенти / вихованці, їхній life-cycle |
| **Групи / класи** | Групи, класи, курси, привʼязані до навчального року |
| **Стипендії: відомості** | Відомості нарахування та виплати стипендій |
| **Харчування** → Меню, Відвідуваність | Дитяче харчування (ЗДО/школи) |
| **Імпорт з ЄДЕБО** / **Експорт у ЄДЕБО** | Обмін контингентом (каркас) |
| **Налаштування** → Навчальні роки, Типи стипендій, Технологічні картки | Довідники |

Тип закладу (ЗДО, ШНЗ, ПТУ, ЗВО I–IV рівнів) задається на **картці компанії**
(`res.company`), а не в модулі.

> _Скриншот:_ `00-apps-menu.png`

## 1. Навчальний рік і групи

**Освіта (UA) → Налаштування → Навчальні роки.** Модуль постачає передзаповнені роки
(`l10n_ua.education.academic.year`). Ключове:

- назва у форматі «2025/2026», `year_end` обчислюється автоматично;
- **активним може бути лише один рік** — система контролює це;
- дати перевіряються на коректність (кінець після початку).

**Освіта (UA) → Групи / класи** (`l10n_ua.education.group`) — група / клас / курс: рівень,
профіль, привʼязка до навчального року (за замовчуванням успадковує активний рік). У картці
групи — лічильник членів.

> _Скриншоти:_ `01-academic-years.png`, `02-groups.png`

## 2. Контингент (учні / студенти / вихованці)

**Освіта (UA) → Контингент** (`l10n_ua.education.contingent.member`). Кожен член контингенту:

- привʼязаний до **`res.partner`** (фізособа), опційно до `hr.employee`;
- має **унікальний номер студента в межах компанії**;
- має чатер (`mail.thread`) для історії й активностей.

**Life-cycle (стани не можна «перестрибувати»):**

```
applicant (абітурієнт) → enrolled (зараховано) → studying (навчається)
                            → graduated (випущено) / expelled (відраховано) / transferred (переведено)
```

Відрахувати можна навіть з етапу «абітурієнт». Перехід одразу на кінцевий стан в обхід
проміжних заборонено (перевірено тестами).

**Створити члена контингенту:** кнопка **Новий** → оберіть фізособу-партнера, групу,
навчальний рік → збережіть. Далі проводьте по станах кнопками статусної панелі.

> _Скриншоти:_ `03-contingent-list.png`, `04-contingent-form.png`

## 3. Стипендії (нарахування)

**Освіта (UA) → Стипендії: відомості** (`l10n_ua.scholarship.payment`).

### 3.1. Типи стипендій

**Налаштування → Типи стипендій** (`l10n_ua.scholarship.type`): академічна, соціальна,
президентська, іменна, стипендія Верховної Ради, обласна. У кожного типу — **ознака
оподаткування** та **КЕКВ за замовчуванням**.

### 3.2. Відомість виплати

Створіть відомість (**Новий**): номер присвоюється послідовністю, КЕКВ за замовчуванням
**2720**, обирається бюджетний фонд, опційно КПКВК. Стани:

```
draft (чернетка) → approved (затверджено) → paid (виплачено) → cancelled (скасовано)
```

- **порожню відомість затвердити не можна**, **оплачену — скасувати не можна**;
- при проведенні контролюється ліміт розпорядника, якщо встановлено
  `l10n_ua_budget_treasury`.

### 3.3. Рядки відомості

Кожен рядок (`l10n_ua.scholarship.payment.line`) — по одному члену контингенту:

- домен вибору — **лише активні студенти**;
- **без дублювання** члена в межах однієї відомості;
- **відʼємна сума заборонена**;
- для **оподатковуваних** типів автоматично рахуються **ПДФО (18 %)** і **ВЗ (5 %)**; для
  неоподатковуваних податок = 0.

> _Скриншоти:_ `05-scholarship-types.png`, `06-scholarship-payment.png`,
> `07-scholarship-lines.png`

## 4. Харчування (meals) — 🟡 каркас

> ⚠️ **Читайте уважно.** Модуль `l10n_ua_education_meals` — **скелет без автотестів**.
> Він **не має пільгових / безоплатних категорій харчування** (див. нижче). Використовуйте
> для меню й обліку порцій, але не для повного розрахунку пільгового харчування.

**Освіта (UA) → Харчування.**

### 4.1. Технологічні картки страв

**Налаштування → Технологічні картки** (`l10n_ua.meal.recipe` +
`l10n_ua.meal.recipe.ingredient`) — рецепти страв з переліком інгредієнтів.

### 4.2. Щоденне меню

**Харчування → Меню** (`l10n_ua.meal.menu` + `l10n_ua.meal.menu.line`): вікова група,
вид прийому їжі (сніданок / обід / полуденок / вечеря), автоматичне підсумовування
**КБЖВ** (калорії, білки, жири, вуглеводи). Стан: `draft → approved`.

### 4.3. Відвідуваність

**Харчування → Відвідуваність** (`l10n_ua.meal.attendance`): присутні / відсутні по
групі-класу, кількість порцій за прийомами їжі — для розрахунку фактичної кількості.

### 4.4. Чого поки НЕМАЄ (чесно)

- **немає пільгових / безоплатних категорій харчування** — облік ведеться лише за
  загальною кількістю порцій і видом прийому їжі; розподіл платні / пільгові / безоплатні
  (діти пільгових категорій за ПКМУ) **не підтримується** — питання відкрите
  (є окремий issue);
- **модель добових вікових норм `l10n_ua.meal.norm` не реалізована** (згадана в маніфесті,
  але моделі й подання немає);
- **немає автотестів** для цього модуля.

> _Скриншоти:_ `08-meal-recipe.png`, `09-meal-menu.png`, `10-meal-attendance.png`

## 5. Обмін з ЄДЕБО (каркас)

> ⚠️ Специфікація форматів ЄДЕБО **закрита** й регулярно оновлюється. Модуль надає **лише
> інфраструктуру** обміну; конкретні формати підключаються плагінами.

### 5.1. Імпорт

**Освіта (UA) → Імпорт з ЄДЕБО** (візард `l10n_ua.edebo.import`): завантаження
студентів/учнів з **CSV / XLSX**. Є **режим сухого прогону (dry-run)** — перевірка без
створення записів — і режим реального створення членів контингенту. Точка розширення
`_parse_custom()` — під власні формати обміну.

### 5.2. Експорт

**Освіта (UA) → Експорт у ЄДЕБО** (візард `l10n_ua.edebo.export`): вивантаження контингенту
в **CSV** (лише активні члени).

### 5.3. XML-плагін (`l10n_ua_education_edebo_xml`)

Окремий модуль-плагін переозначує `_parse_custom()` для формату `custom` і парсить **XML**
за структурою `<edebo><students><student>…` з підтримкою синонімів тегів (`TAG_SYNONYMS`).
Структуру переозначують у дочірньому модулі під реальний контракт МОН.

- вибір формату `custom` **без встановленого плагіна** дає помилку (перевірено тестами);
- **експорт у XML ще не реалізовано** (потребує цифрового підпису — окремий PR).

> _Скриншоти:_ `11-edebo-import.png`, `12-edebo-export.png`

## Поточний стан

Домен **🟡 бета**. Що реально працює й покрито тестами, а що ні:

| Складова | Стан | Тести |
|----------|------|-------|
| `l10n_ua_education_base` (контингент, роки, групи) | 🟢 робочий | 11 тестів |
| `l10n_ua_education_scholarship` (стипендії) | 🟢 робочий | 11 тестів |
| `l10n_ua_education_edebo` (CSV/XLSX-каркас) | 🟢 каркас | 6 тестів |
| `l10n_ua_education_edebo_xml` (XML-плагін) | 🟢 каркас | 5 тестів |
| `l10n_ua_education_meals` (харчування) | 🟡 **скелет** | **немає тестів** |

**Чесні застереження:**

- **ЄДЕБО — це каркас, а не готовий обмін.** Реальні формати закриті; вбудована XML-структура
  є робочим прикладом, який переозначується під контракт МОН. Експорт у XML ще не готовий.
- **Харчування без пільгових/безоплатних категорій.** Немає розподілу порцій на платні /
  пільгові / безоплатні (діти пільгових категорій за ПКМУ), немає моделі добових норм і
  немає автотестів. Питання про пільгові категорії — відкритий issue.
