## Поточний стан

> Прочитайте цей розділ **першим** — він визначає, що реально працює, а що ні.

| Функція | Стан |
|---------|------|
| Базові поля перевізника (`delivery.carrier`) | 🟢 реалізовано |
| Довідник відділень / поштоматів (`l10n_ua.delivery.warehouse`) | 🟢 реалізовано |
| Посилання на відстеження (tracking link) | 🟢 формується як URL із `carrier_tracking_ref` |
| Розрахунок вартості доставки | 🟡 заглушка — повертає `price = 0.0` |
| Створення ТТН / накладної | 🟡 заглушка — порожній `tracking_number` |
| Скасування ТТН | 🟡 заглушка — `pass` |
| Синхронізація довідника відділень з API | 🟡 заглушка — `# TODO`, `pass` |
| Друк маркування | 🟡 не реалізовано |

**Що це означає на практиці:**

- Модулі `l10n_ua_delivery_novaposhta`, `l10n_ua_delivery_ukrposhta`, `l10n_ua_delivery_meest`
  **не роблять реальних викликів API** перевізників. Усі методи створення відправлень,
  розрахунку вартості та синхронізації містять `# TODO` і повертають нульові / порожні значення.
- Абстрактний mixin `l10n_ua.delivery.mixin` описує лише **інтерфейс** (`ua_create_shipment`,
  `ua_get_tracking`, `ua_calculate_cost`, `ua_get_warehouses`, `ua_print_label`) — усі його
  методи викидають `NotImplementedError`.
- Автоматизованих тестів у домені **немає**.
- Єдине, що працює «наскрізь», — формування **посилання на відстеження**: якщо у відвантаженні
  вручну заповнити номер ТТН (`carrier_tracking_ref`), система збудує коректний URL на трекінг
  перевізника.

Отже, домен придатний для **налаштування перевізників і ведення довідника відділень**; фактичну
ТТН поки що доводиться створювати в кабінеті перевізника й вносити її номер у відвантаження
вручну. Нижче — **Флоу 1** (повністю робочий) і **Флоу 2** (планований, кроки з викликами API
не виконуються автоматично).

> _Скриншот меню:_ `00-menu.png`

Функціонал доставки розподілений між двома місцями:

- **Склад → Конфігурація → Способи доставки** (стандартні перевізники Odoo, `delivery.carrier`) —
  тут задаються українські поля перевізника;
- **меню `Delivery` (Доставка)** в українському кореневому меню (`l10n_ua_account_base`) →
  **Warehouses (Відділення)** — довідник відділень / поштоматів.

## Флоу 1. Налаштування перевізника

> Повністю робочий процес: створення способу доставки з українськими полями та наповнення
> довідника відділень. Результат — перевізник доступний для вибору у відвантаженнях і продажах.

### Крок 1. Створити спосіб доставки та заповнити базові поля перевізника

**Склад → Конфігурація → Способи доставки → кнопка `Новий`.** Створіть спосіб доставки для
потрібного перевізника (Нова Пошта / Укрпошта / Meest). Модуль `l10n_ua_delivery_base` додає до
картки українські поля конфігурації:

| Поле | Призначення |
|------|-------------|
| `ua_carrier_type` — тип перевізника | `novaposhta` / `meest` / `ukrposhta` |
| `ua_api_key` — ключ API | ключ доступу до API перевізника |
| `ua_sender_ref` — референс відправника | ID відправника в системі перевізника |
| `ua_sender_address_ref` — референс адреси | ID адреси відправника |
| `ua_sender_contact_ref` — референс контакту | ID контакту відправника |
| `ua_default_service_type` — тип послуги | склад-склад / склад-двері / двері-склад / двері-двері (за замовч. `warehouse`) |
| `ua_default_payment_method` — платник | відправник / отримувач / третя сторона (за замовч. `sender`) |
| `ua_cod_enabled` — післяплата (COD) | увімкнення накладеного платежу |

Модуль **Нова Пошта** додатково додає поле `np_api_url` (за замовчуванням
`https://api.novaposhta.ua/v2.0/json/`). Модулі **Укрпошта** та **Meest** власних полів до картки
перевізника не додають.

> **Зверніть увагу:** заповнення `ua_api_key` та референсів **не активує** обмін із перевізником —
> код, що мав би використати ці значення для викликів API, наразі є заглушкою (див.
> [«Поточний стан»](#поточний-стан)). Поля існують як заготовка під майбутню інтеграцію.

> _Скриншот:_ `01-carrier-config.png`

### Крок 2. Наповнити довідник відділень / поштоматів

**Delivery (Доставка) → Warehouses (Відділення) → кнопка `Новий`.** Модель
`l10n_ua.delivery.warehouse` — спільний довідник відділень і поштоматів для всіх перевізників.
Це **повністю робоча** частина домену. Поля запису:

| Поле | Призначення |
|------|-------------|
| `name` | назва відділення |
| `carrier_type` | до якого перевізника належить |
| `warehouse_ref` | референс у системі перевізника |
| `warehouse_number` | номер відділення |
| `warehouse_type` | тип: склад / поштомат / вантажний |
| `city`, `city_ref` | місто та його референс |
| `address`, `phone`, `schedule` | адреса, телефон, графік |
| `max_weight` | максимальна вага |
| `latitude`, `longitude` | координати |
| `active` | активність |

Особливості довідника:

- обмеження унікальності `UNIQUE(warehouse_ref, carrier_type)` — одне відділення на перевізника
  не дублюється;
- кастомний пошук (`name_search`) працює за **назвою, номером відділення та містом** — зручно
  вибирати відділення у полях типу «куди доставити».

> **Наповнення:** оскільки автоматична синхронізація з API — заглушка (`np_sync_warehouses`,
> `ukrposhta_sync_branches`, `meest_sync_warehouses` містять `# TODO`), відділення поки що
> **вносяться вручну** (кнопка `Новий`) або імпортом. На кнопку «синхронізувати з перевізником»
> покладатися не варто — вона нічого не завантажить.

> _Скриншоти:_ `02-warehouses-list.png`, `03-warehouse-form.png`

### Результат

Перевізник із заповненими українськими полями та довідник відділень доступні для вибору у
відвантаженнях (`stock.picking`) і продажах. Номер ТТН у поле відстеження поки вноситься вручну
(див. Флоу 2).

## Флоу 2. (планований) Створення ТТН / відстеження

> **Проєктний задум** флоу — як воно має працювати після реалізації інтеграцій, щоб було
> зрозуміло призначення полів. Наразі кроки з викликами API **не виконуються автоматично**;
> позначки стану показують, що реально працює вже сьогодні.

### Крок 1. Розрахунок вартості доставки

При оформленні продажу / відвантаження перевізник мав би повернути ціну доставки
(`np_rate_shipment` / `ukrposhta_rate_shipment` / `meest_rate_shipment`).
_Стан:_ 🟡 заглушка, повертає `0.0` — реального виклику API немає.

### Крок 2. Створення ТТН / накладної

При підтвердженні відвантаження (`stock.picking`) мав би створитися документ перевізника й
повернутися номер відстеження в `carrier_tracking_ref`
(`np_send_shipping` / `ukrposhta_send_shipping` / `meest_send_shipping`).
_Стан:_ 🟡 заглушка, номер порожній → **вносьте номер ТТН вручну**.

### Крок 3. Друк маркування

Формування етикетки перевізника (`ua_print_label`).
_Стан:_ 🟡 не реалізовано.

### Крок 4. Відстеження (працює вже сьогодні)

За номером ТТН система будує посилання на трекінг перевізника
(`np_get_tracking_link` / `ukrposhta_get_tracking_link` / `meest_get_tracking_link`).
_Стан:_ 🟢 **працює** — щойно заповните `carrier_tracking_ref`, отримаєте коректний URL.

### Крок 5. Скасування ТТН

Скасування раніше створеної накладної (`*_cancel_shipment`).
_Стан:_ 🟡 заглушка, `pass`.

### Результат / робочий обхідний варіант сьогодні

Створіть ТТН у кабінеті перевізника, впишіть її номер у поле відстеження відвантаження
(`carrier_tracking_ref`) — і посилання на трекінг (Крок 4) сформується коректно. Розрахунок
вартості, автоматичне створення ТТН, друк маркування та скасування наживо поки недоступні.

> _Скриншот:_ `04-tracking-link.png`
