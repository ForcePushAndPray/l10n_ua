# HOWTO: Доставка (українські перевізники)

← [Назад до документації](../../README.md) · [Опис домену](../delivery.md)

> Покроковий сценарій, звірений наживо на **[demo.ndev.online](https://demo.ndev.online)**
> (компанія _ТОВ «Тестова Компанія»_). Дані на демо **не видаляються** — його можна
> наповнювати під час тестування.
>
> **Важливо:** цей домен реалізовано лише частково. Готова інфраструктура (налаштування
> перевізника та довідник відділень), а самі інтеграції API Нової Пошти / Укрпошти / Meest —
> **каркасні** (методи-заглушки). Див. розділ [«Поточний стан»](#поточний-стан) — не
> розраховуйте на автоматичне створення ТТН, розрахунок вартості чи синхронізацію відділень.

Скріншоти — у теці [`img/delivery/`](img/delivery/).

## Поточний стан

> Прочитайте цей розділ **першим** — він визначає, що реально працює, а що ні.

| Функція | Стан |
|---------|------|
| Базові поля перевізника (`delivery.carrier`) | 🟢 реалізовано |
| Довідник відділень / поштоматів (`l10n_ua.delivery.warehouse`) | 🟢 реалізовано |
| Розрахунок вартості доставки | 🟡 заглушка — повертає `price = 0.0` |
| Створення ТТН / накладної | 🟡 заглушка — порожній `tracking_number` |
| Скасування ТТН | 🟡 заглушка — `pass` |
| Синхронізація довідника відділень з API | 🟡 заглушка — `# TODO`, `pass` |
| Друк маркування | 🟡 не реалізовано |
| Посилання на відстеження (tracking link) | 🟢 формується як URL із `carrier_tracking_ref` |

**Що це означає на практиці:**

- Модулі `l10n_ua_delivery_novaposhta`, `l10n_ua_delivery_ukrposhta`, `l10n_ua_delivery_meest`
  **не роблять реальних викликів API** перевізників. Усі методи створення відправлень,
  розрахунку вартості та синхронізації містять `# TODO` і повертають нульові / порожні
  значення.
- Абстрактний mixin `l10n_ua.delivery.mixin` описує лише **інтерфейс** (`ua_create_shipment`,
  `ua_get_tracking`, `ua_calculate_cost`, `ua_get_warehouses`, `ua_print_label`) — усі його
  методи викидають `NotImplementedError`.
- Автоматизованих тестів у домені **немає**.
- Єдине, що працює «наскрізь», — це формування **посилання на відстеження**: якщо у
  відвантаженні вручну заповнити номер ТТН (`carrier_tracking_ref`), система збудує коректний
  URL на трекінг перевізника.

Отже, домен придатний для **налаштування перевізників і ведення довідника відділень**;
фактичну ТТН поки що доводиться створювати в кабінеті перевізника й вносити її номер у
відвантаження вручну.

## 0. Де шукати

Функціонал доставки розподілений між двома місцями:

- **Склад → Конфігурація → Способи доставки** (стандартні перевізники Odoo, `delivery.carrier`) —
  тут задаються українські поля перевізника;
- **меню `Delivery` (Доставка)** в українському кореневому меню (`l10n_ua_account_base`) →
  **Warehouses (Відділення)** — довідник відділень / поштоматів.

> _Скриншот:_ `00-menu.png`

## 1. Налаштування перевізника (delivery.carrier)

**Склад → Конфігурація → Способи доставки → Новий.** Створіть спосіб доставки для потрібного
перевізника (Нова Пошта / Укрпошта / Meest). Модуль `l10n_ua_delivery_base` додає до картки
українські поля конфігурації:

| Поле | Призначення |
|------|-------------|
| `ua_carrier_type` — тип перевізника | `novaposhta` / `meest` / `ukrposhta` |
| `ua_api_key` — ключ API | ключ доступу до API перевізника |
| `ua_sender_ref` — референс відправника | ID відправника в системі перевізника |
| `ua_sender_address_ref` — референс адреси | ID адреси відправника |
| `ua_sender_contact_ref` — референс контакту | ID контакту відправника |
| `ua_default_service_type` — тип послуги | склад-склад / склад-двері / двері-склад / двері-двері (за замовч. `warehouse`) |
| `ua_default_payment_method` — платник | відправник / отримувач / третя сторона (за замовч. `sender`) |
| `ua_cod_enabled` — післяплата (COD) | увімкнення накладеного платежу |

Модуль **Нова Пошта** додатково додає поле `np_api_url` (за замовчуванням
`https://api.novaposhta.ua/v2.0/json/`). Модулі **Укрпошта** та **Meest** власних полів до
картки перевізника не додають.

> **Зверніть увагу:** заповнення `ua_api_key` та референсів **не активує** обмін із
> перевізником — код, що мав би використати ці значення для викликів API, наразі є заглушкою
> (див. [«Поточний стан»](#поточний-стан)). Поля існують як заготовка під майбутню інтеграцію.

> _Скриншот:_ `01-carrier-config.png`

## 2. Довідник відділень / поштоматів

**Delivery (Доставка) → Warehouses (Відділення).** Модель `l10n_ua.delivery.warehouse` —
спільний довідник відділень і поштоматів для всіх перевізників. Це **повністю робоча**
частина домену.

Поля запису відділення:

- `name` — назва; `carrier_type` — до якого перевізника належить;
- `warehouse_ref` — референс у системі перевізника; `warehouse_number` — номер відділення;
- `warehouse_type` — тип: склад / поштомат / вантажний;
- `city`, `city_ref` — місто та його референс; `address`, `phone`, `schedule` — адреса,
  телефон, графік;
- `max_weight` — максимальна вага; `latitude`, `longitude` — координати; `active` — активність.

Особливості:

- обмеження унікальності `UNIQUE(warehouse_ref, carrier_type)` — одне відділення на перевізника
  не дублюється;
- кастомний пошук (`name_search`) працює за **назвою, номером відділення та містом** — зручно
  вибирати відділення у полях типу «куди доставити».

**Наповнення довідника.** Оскільки автоматична синхронізація з API — заглушка
(`np_sync_warehouses`, `ukrposhta_sync_branches`, `meest_sync_warehouses` містять `# TODO`),
відділення поки що **вносяться вручну** (кнопка **Новий**) або імпортом. Кнопки «синхронізувати
з перевізником» покладатися не варто — вона нічого не завантажить.

> _Скриншоти:_ `02-warehouses-list.png`, `03-warehouse-form.png`

## 3. Що передбачається у флоу ТТН / відстеження

Нижче — **проєктний задум** флоу (як воно має працювати після реалізації інтеграцій), щоб було
зрозуміло призначення полів. Наразі кроки з викликами API **не виконуються автоматично**.

1. **Розрахунок вартості** — при оформленні продажу/відвантаження перевізник мав би повернути
   ціну доставки (`np_rate_shipment` / `ukrposhta_rate_shipment` / `meest_rate_shipment`).
   _Стан:_ заглушка, повертає `0.0`.
2. **Створення ТТН/накладної** — при підтвердженні відвантаження (`stock.picking`) мав би
   створитися документ перевізника й повернутися номер відстеження в `carrier_tracking_ref`
   (`np_send_shipping` / `ukrposhta_send_shipping` / `meest_send_shipping`).
   _Стан:_ заглушка, номер порожній → **вносьте номер ТТН вручну**.
3. **Друк маркування** — формування етикетки (`ua_print_label`). _Стан:_ не реалізовано.
4. **Відстеження** — за номером ТТН система будує посилання на трекінг перевізника
   (`np_get_tracking_link` / `ukrposhta_get_tracking_link` / `meest_get_tracking_link`).
   _Стан:_ **працює** — щойно заповните `carrier_tracking_ref`, отримаєте коректний URL.
5. **Скасування ТТН** — `*_cancel_shipment`. _Стан:_ заглушка, `pass`.

**Робочий обхідний варіант сьогодні:** створіть ТТН у кабінеті перевізника, впишіть її номер у
поле відстеження відвантаження — і посилання на трекінг сформується коректно.

> _Скриншот:_ `04-tracking-link.png`
