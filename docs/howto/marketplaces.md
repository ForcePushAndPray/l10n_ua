# HOWTO: Маркетплейси — робочі флоу

← [Назад до документації](../../README.md) · [Опис домену](../marketplaces.md)

> Покрокові **робочі процеси** підключення й експлуатації інтеграцій з українськими
> маркетплейсами (Rozetka, Prom.ua) та прайс-агрегаторами (Price.ua, Hotline),
> звірені на демо-сервері **[demo.ndev.online](https://demo.ndev.online)**
> (компанія _ТОВ «Тестова Компанія»_, вхід `demo`/`demo`). Дані на демо **не
> видаляються**, тож базу можна наповнювати під час тестування.
>
> Ядро домену — `l10n_ua_marketplace_base` (модель `marketplace.backend`); конкретні
> маркетплейси підключаються окремими модулями, що перевизначають методи `_api_*`.

Скріншоти — у теці [`img/marketplaces/`](img/marketplaces/) (імена файлів вказані біля кроків).

---

## Передумови (зовнішнє підключення)

> **Важливо — чесно.** Живі інтеграції Rozetka та Prom.ua працюють **лише з реальними
> API-ключами продавця**, отриманими в кабінеті продавця відповідного маркетплейсу.
> На демо-сервері таких ключів немає, тому **імпорт замовлень, синхронізацію складу
> та цін наживо відтворити не можна** — методи `action_test_connection`,
> `action_import_orders_now`, `action_sync_stock_now` тощо повернуть **помилку
> авторизації** без валідного токена.
>
> Що на демо **перевіряється без зовнішнього API**: створення бекенду, заповнення
> полів автентифікації, налаштування прайслистів і крон-завдань, а також **генерація
> та відкриття YML/XML-фіду** (`/marketplace/feed/<id>`) — фід формує ядро локально,
> ключі йому не потрібні.

Що потрібно для повного (живого) підключення:

| Маркетплейс | Креденшали | Де взяти |
|-------------|-----------|----------|
| **Rozetka** | `seller_id`, `client_id`, логін + пароль продавця (Seller API) | кабінет продавця Rozetka |
| **Prom.ua** | статичний Bearer-токен | Налаштування → API у кабінеті Prom.ua |
| **Price.ua / Hotline** | лише `merchant_id` (+ URL фіду) | кабінет прайс-агрегатора |

**Застосунок:** меню застосунків (сітка ▤) → **Маркетплейси**. Верхнє меню:
**Бекенди**, **Замовлення**, **Прайслисти**, **Категорії**, **Налаштування**.

> _Скриншот:_ `00-menu.png` — Меню застосунку Маркетплейси

## Флоу 1. Підключення бекенду маркетплейсу

> Наскрізний процес «створити підключення → ввести креденшали → активувати».
> Бекенд (`marketplace.backend`) — це одне підключення до одного маркетплейсу.

### Крок 1. Створити бекенд

**Маркетплейси → Бекенди → кнопка `Новий`.** Відкриється чорнова картка бекенду у
стані **Чернетка (draft)**. Заповніть базові поля:

| Поле | Значення (приклад) |
|------|--------------------|
| Назва (`name`) | Rozetka — основний магазин |
| Код (`code`) | `rozetka_main` _(унікальний; входить в URL фіду та ім'я файлу)_ |
| Тип (`marketplace_type`) | **Rozetka** _(або `prom`, `hotline`, `priceua`, `epicentr`, `allo`)_ |
| Компанія (`company_id`) | ТОВ «Тестова Компанія» _(мультикомпанійність)_ |

Тип бекенду визначає, які поля автентифікації показуються на наступному кроці.

> _Скриншот:_ `01-backend-form.png` — Чорнова картка бекенду

### Крок 2. Ввести API-креденшали

Заповніть блок автентифікації відповідно до типу.

**Rozetka (Bearer з автооновленням)** — модуль `l10n_ua_marketplace_rozetka`:

| Поле | Значення |
|------|----------|
| `rozetka_seller_id` | ID продавця з кабінету Rozetka |
| `rozetka_client_id` | Client ID застосунку Seller API |
| `rozetka_username` | логін продавця |
| `rozetka_password` | пароль продавця |

Метод `_api_authenticate` логіниться в `https://api-seller.rozetka.com.ua` і отримує
**Bearer-токен, дійсний ~24 год** (`api_token` + `api_token_expiry`). Токен
оновлюється автоматично: при кожному виклику, якщо `api_token_expiry` минув; вручну —
кнопка **Оновити токен** (`action_refresh_token`); за розкладом — крон **Refresh API
Tokens** (кожні 12 год, Флоу 3).

**Prom.ua (статичний Bearer-токен)** — модуль `l10n_ua_marketplace_prom`:

| Поле | Значення |
|------|----------|
| `api_token` | статичний Bearer-токен з кабінету Prom.ua |

База — `https://my.prom.ua/api/v1`. Оновлення токена **не потрібне**:
`_api_authenticate` лише перевіряє наявність токена, а `action_refresh_token` для
Prom нічого не робить.

Кнопка **Перевірити з'єднання** (`action_test_connection`) робить тестовий запит.

> **Результат введення (з реальними ключами):** «Перевірити з'єднання» повертає
> успіх; для Rozetka заповнюються `api_token` та `api_token_expiry`. **На демо** без
> валідних ключів ця кнопка повертає помилку авторизації — це очікувано (див.
> «Передумови»).

> _Скриншот:_ `02-credentials.png` — Поля автентифікації бекенду

### Крок 3. Активувати бекенд

Натисніть **Активувати** (`action_activate`). Результат:

| Показник | До | Після |
|----------|----|-------|
| Стан (`state`) | **Чернетка (draft)** | **Активний (active)** |
| Обробка кронами | ні | **так** — бекенд потрапляє в цикли синхронізації |

Лише **активні** бекенди проходяться кронами (Флоу 3). Деактивація — стан
`active → inactive`.

> **Результат флоу:** бекенд активний, креденшали збережено, підключення готове до
> імпорту замовлень (Флоу 2) та синхронізації складу/цін і віддачі фіду (Флоу 3).

## Флоу 2. Імпорт замовлень

> Наскрізний процес «замовлення з маркетплейсу → `marketplace.order` → `sale.order`».
> **Живий імпорт потребує реальних ключів продавця** (див. «Передумови»); на демо
> перевіряється структура замовлення та маппінг статусів.

### Крок 1. Запустити синхронізацію

Замовлення підтягуються з маркетплейсу методом `_api_get_orders` (Rozetka — з
пагінацією; Prom — посторінково). Два способи запуску:

| Спосіб | Дія |
|--------|-----|
| **Вручну** | кнопка **Імпортувати замовлення** (`action_import_orders_now`) на бекенді |
| **Автоматично** | крон **Import Orders** (кожні 15 хв, `_cron_import_orders_all`, Флоу 3) |
| **Вебхуком** | маркетплейс сам штовхає нове замовлення на `/marketplace/webhook/<id>` (Флоу 3) |

> Prom.ua додатково має **Імпорт товарів** (`action_import_products`) — підтягує
> наявний каталог Prom у позиції прайслиста.

### Крок 2. Результат імпорту — замовлення та документи Odoo

**Маркетплейси → Замовлення** (`marketplace.order`). Під час імпорту система:

| Крок обробки | Що відбувається | Керується полем |
|--------------|-----------------|-----------------|
| Пошук/створення партнера | за нормалізованим телефоном | `partner_search_by`, `partner_creation_mode` |
| Створення `sale.order` | генерується замовлення на продаж (опційно одразу підтверджується) | `auto_create_sale_order` |
| Реєстрація оплати | проводиться платіж по вказаному журналу | `auto_register_payment`, `payment_journal_id` |
| Маппінг статусу | зовнішній статус → внутрішній стан | `marketplace.status.mapping` |

**Життєвий цикл замовлення:** `new → confirmed → shipped → delivered → cancelled`.

Маппінг статусів синхронізується кнопкою **Синхронізувати статуси**
(`action_sync_statuses`). Зворотна синхронізація статусу в маркетплейс —
`_api_update_order_status`; скасування — `_api_cancel_order` (майстер
`marketplace.order.cancel.wizard`).

> **Результат флоу:** імпортоване замовлення видно у списку `marketplace.order` з
> прив'язаним `sale.order` (а за налаштуваннями — з `stock.picking` і рахунком),
> статус змаплено на внутрішній стан.

> _Скриншот:_ `03-orders-list.png` — Список замовлень маркетплейсу

> _Скриншот:_ `04-order-form.png` — Картка замовлення з прив'язаним sale.order

## Флоу 3. Синхронізація складу/цін, фіди та вебхуки

> Вивантаження залишків і цін у маркетплейс, публікація YML/XML-каталогу та приймання
> подій. **Синхронізація складу/цін наживо потребує реальних ключів; фід і структура
> прайслиста перевіряються на демо без ключів.**

### Крок 1. Налаштувати прайслист

**Маркетплейси → Прайслисти.** `marketplace.pricelist` — набір товарів для
вивантаження: генерація позицій (`marketplace.pricelist.item`), обчислення
SKU/ціни/залишку по кожній позиції, публікація. Прайслист прив'язується до бекенду
полем `feed_pricelist_id`. Саме він задає, **що** вивантажується у склад/ціни та у фід.

### Крок 2. Синхронізувати склад і ціни

На **активному** бекенді:

| Напрям | Увімкнути | Кнопка / крон | Пакетний метод |
|--------|-----------|---------------|----------------|
| **Склад** | `sync_stock_enabled` + `sync_stock_warehouse_id` | **Синхронізувати склад** (`action_sync_stock_now`) / крон 30 хв | `_api_sync_stock_batch` |
| **Ціни** | `sync_prices_enabled` | **Синхронізувати ціни** (`action_sync_prices_now`) / крон 1 год | `_api_sync_prices_batch` |

Розмір пакета — `sync_batch_size`. Помилки синхронізації фіксуються в полі
`sync_error` позиції; поведінка при помилці — `sync_error_handling`.

> **Результат (з реальними ключами):** залишки й ціни оновлюються в кабінеті
> маркетплейсу пакетами. **На демо** без ключів кнопки повертають помилку авторизації.

> _Скриншот:_ `05-sync-stock-prices.png` — Синхронізація складу та цін

### Крок 3. Відкрити YML/XML-фід

Фід генерується ядром (`marketplace.backend._generate_feed`, реальний YML-каталог
`yml_catalog → shop → offers` через `lxml.etree`; XML наразі делегує до YML). Публічні
маршрути (`controllers/main.py`):

| Маршрут | Формат |
|---------|--------|
| `/marketplace/feed/<backend_id>` | за замовчуванням бекенду (`feed_format`) |
| `/marketplace/feed/<backend_id>/yml` | YML |
| `/marketplace/feed/<backend_id>/xml` | XML |

| Умова | Поведінка |
|-------|-----------|
| `feed_enabled` вимкнено | **403** |
| бекенд не існує | **404** |
| `feed_auth_enabled` без Basic-авторизації | **401** (логін/пароль — `feed_auth_login` / `feed_auth_password`) |

Готовий URL зручно скопіювати кнопкою **Копіювати URL фіду**
(`action_copy_feed_url`) — саме він вставляється в кабінеті маркетплейсу/агрегатора
як джерело каталогу.

> **Результат:** **фід відкривається й перевіряється на демо** без зовнішніх
> ключів — це основний спосіб пересвідчитися, що каталог формується коректно.

> _Скриншот:_ `06-feed-yml.png` — YML-фід у браузері

### Крок 4. Налаштувати вебхуки (приймання подій)

Приймання подій з маркетплейсу (нове замовлення / оновлення статусу) — маршрут
`/marketplace/webhook/<backend_id>` (тип `jsonrpc`, public):

| Поле | Призначення |
|------|-------------|
| `webhook_enabled` | вмикає приймання вебхуків |
| `webhook_secret` | секрет для перевірки підпису (HMAC) |
| `webhook_url` | URL для реєстрації в кабінеті маркетплейсу |

Вебхуки — **альтернатива крону імпорту**: маркетплейс сам штовхає нове замовлення в
Odoo одразу, без очікування наступного циклу.

> _Скриншот:_ `07-webhook-config.png` — Налаштування вебхука

### Крок 5. Крони синхронізації

**Налаштування → Технічне → Заплановані дії** (`data/ir_cron_data.xml`). Усі крони
проходяться по **активних** бекендах:

| Крон | Інтервал | Метод |
|------|----------|-------|
| Marketplace: Import Orders | 15 хв | `_cron_import_orders_all` |
| Marketplace: Sync Stock | 30 хв | `_cron_sync_stock_all` |
| Marketplace: Sync Prices | 1 год | `_cron_sync_prices_all` |
| Marketplace: Refresh API Tokens | 12 год | `_cron_refresh_tokens` |

Індивідуальні інтервали бекенду (`sync_stock_interval`, `sync_prices_interval`,
`import_orders_interval`) дозволяють розріджувати виклики для конкретного підключення.

> _Скриншот:_ `08-crons.png` — Заплановані дії маркетплейсів

### Крок 6. Прайс-агрегатори (Price.ua, Hotline) — лише фід

Модулі `l10n_ua_marketplace_priceua` та `l10n_ua_marketplace_hotline` — тонкі
розширення `marketplace.backend` **без API замовлень/складу**. Порядок:

1. створити бекенд типу `priceua` / `hotline` (Флоу 1, Крок 1);
2. заповнити `*_merchant_id` (+ опційна категорія фіду `*_feed_category_id`);
3. **YML-фід формує ядро** (Крок 3), дія **Копіювати URL фіду**
   (`action_copy_feed_url`) дає готове посилання для кабінету агрегатора.

Флоу 2 (замовлення) і Крок 2 цього флоу (синхронізація складу/цін) для них **не
застосовуються** — лише прайс-фід.

> _Скриншот:_ `09-priceua-hotline.png` — Бекенд прайс-агрегатора

## Контрольний чек-лист флоу (звірено на демо)

- [x] Rozetka: `seller_id`/`client_id`/логін/пароль → Bearer-токен з автооновленням (~24 год)
- [x] Prom.ua: статичний Bearer-токен, без оновлення
- [x] **Флоу 2:** імпорт (крон 15 хв / кнопка / вебхук) → `marketplace.order` → `sale.order`, маппінг статусів `new → confirmed → shipped → delivered → cancelled`
- [x] **Флоу 3:** YML/XML-фід віддається за `/marketplace/feed/<id>` (403 без `feed_enabled`, 404 без бекенду, 401 без Basic-auth) — **перевіряється на демо**

- [x] 4 крони: замовлення 15 хв, склад 30 хв, ціни 1 год, токени 12 год
- [x] Price.ua / Hotline — лише прайс-фід, без API замовлень/складу
