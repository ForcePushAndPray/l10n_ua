# HOWTO: Маркетплейси (Rozetka, Prom, прайс-агрегатори)

← [Назад до документації](../../README.md) · [Опис домену](../marketplaces.md)

> Покроковий сценарій налаштування інтеграцій з українськими маркетплейсами, звірений
> наживо на демо-сервері **[demo.ndev.online](https://demo.ndev.online)**
> (компанія _ТОВ «Тестова Компанія»_, користувач `demo`).
>
> Дані на демо-сервері **не видаляються** — його можна наповнювати в процесі тестування.

Скріншоти до кожного кроку — у теці [`img/marketplaces/`](img/marketplaces/) (імена файлів
вказані біля кроків).

---

## Передумови (зовнішнє підключення)

> **Важливо — чесно.** Живі інтеграції Rozetka та Prom.ua працюють **лише з реальними
> API-ключами продавця**, отриманими в кабінеті продавця відповідного маркетплейсу.
> На демо-сервері таких ключів немає, тому:
>
> - **імпорт замовлень, синхронізацію складу та цін наживо відтворити не можна** —
>   `action_test_connection`, `action_import_orders_now` тощо повернуть помилку
>   авторизації без валідного токена;
> - на демо **можна перевірити** все, що не потребує зовнішнього API: створення бекенду,
>   заповнення полів, генерацію та відкриття **YML/XML-фіду** (`/marketplace/feed/<id>`),
>   налаштування прайслистів і крон-завдань.
>
> Що потрібно для повного підключення:
>
> | Маркетплейс | Креденшали | Де взяти |
> |-------------|-----------|----------|
> | **Rozetka** | логін + пароль продавця (Seller API) | кабінет продавця Rozetka |
> | **Prom.ua** | статичний Bearer-токен | Налаштування → API у кабінеті Prom.ua |
> | **Price.ua / Hotline** | лише `merchant_id` + URL фіду | кабінет прайс-агрегатора |

## 0. Застосунок

Меню застосунків (сітка ▤) → **Маркетплейси**. Верхнє меню: **Бекенди**, **Замовлення**,
**Прайслисти**, **Категорії**, **Налаштування**.

> _Скриншот:_ `00-menu.png`

## 1. Створення бекенду маркетплейсу

**Маркетплейси → Бекенди → Новий.** Бекенд (`marketplace.backend`) — це одне підключення до
одного маркетплейсу. Ключові поля:

| Поле | Призначення |
|------|-------------|
| **Назва** (`name`) | Довільна назва підключення |
| **Код** (`code`) | Унікальний код; входить в URL фіду та ім'я файлу |
| **Тип** (`marketplace_type`) | `rozetka`, `prom`, `hotline`, `priceua`, `epicentr`, `allo` |
| **Компанія** (`company_id`) | Компанія-власник (мультикомпанійність) |
| **Стан** (`state`) | `draft → active → inactive` |

Новий бекенд створюється у стані **Чернетка (draft)**. Після заповнення креденшалів
натисніть **Активувати** (`action_activate`) — стан зміниться на **Активний (active)**.
Лише активні бекенди обробляються кронами.

> _Скриншот:_ `01-backend-form.png`

## 2. API-креденшали

Тип бекенду визначає, які поля автентифікації показуються.

### 2.1. Rozetka (Bearer з автооновленням)

Модуль `l10n_ua_marketplace_rozetka`. Заповнюються поля продавця:
`rozetka_seller_id`, `rozetka_client_id`, `rozetka_username`, `rozetka_password`.

Метод `_api_authenticate` логіниться в `https://api-seller.rozetka.com.ua` і отримує
**Bearer-токен, дійсний ~24 год** (`api_token` + `api_token_expiry`). Токен оновлюється
автоматично:

- при кожному виклику, якщо `api_token_expiry` минув;
- вручну — кнопка **Оновити токен** (`action_refresh_token`);
- за розкладом — крон **Refresh API Tokens** (кожні 12 год, крок 7).

Кнопка **Перевірити з'єднання** (`action_test_connection`) робить тестовий запит.

### 2.2. Prom.ua (статичний Bearer-токен)

Модуль `l10n_ua_marketplace_prom`. У полі `api_token` вказується **статичний Bearer-токен**
з кабінету Prom.ua — база `https://my.prom.ua/api/v1`. Оновлення токена **не потрібне**:
`_api_authenticate` лише перевіряє наявність токена, а `action_refresh_token` для Prom
нічого не робить.

> _Скриншот:_ `02-credentials.png`

## 3. Імпорт замовлень

**Маркетплейси → Замовлення** (`marketplace.order`). Замовлення підтягуються з маркетплейсу
методом `_api_get_orders` (Rozetka — з пагінацією; Prom — посторінково).

Ручний запуск — кнопка **Імпортувати замовлення** (`action_import_orders_now`) на бекенді;
автоматичний — крон **Import Orders** (кожні 15 хв, крок 7).

Життєвий цикл замовлення: **`new → confirmed → shipped → delivered → cancelled`**.
Під час імпорту система:

- шукає/створює партнера за нормалізованим телефоном (`partner_search_by`,
  `partner_creation_mode`);
- створює `sale.order` (за `auto_create_sale_order`, опційно одразу підтверджує);
- за потреби реєструє оплату (`auto_register_payment`, журнал `payment_journal_id`);
- маппить зовнішній статус на внутрішній через `marketplace.status.mapping`
  (кнопка **Синхронізувати статуси** / `action_sync_statuses`).

Зворотна синхронізація статусу в маркетплейс — `_api_update_order_status`; скасування —
`_api_cancel_order` (з майстром `marketplace.order.cancel.wizard`).

> Prom.ua додатково має **Імпорт товарів** (`action_import_products`) — підтягує наявний
> каталог Prom у позиції прайслиста.

> _Скриншоти:_ `03-orders-list.png`, `04-order-form.png`

## 4. Синхронізація складу та цін

На активному бекенді:

- **Склад** — увімкнути `sync_stock_enabled`, вказати `sync_stock_warehouse_id`; кнопка
  **Синхронізувати склад** (`action_sync_stock_now`) або крон (30 хв). Пакетне оновлення —
  `_api_sync_stock_batch`, розмір пакета — `sync_batch_size`;
- **Ціни** — `sync_prices_enabled`; кнопка **Синхронізувати ціни**
  (`action_sync_prices_now`) або крон (1 год); пакет — `_api_sync_prices_batch`.

Що саме вивантажується, задає **прайслист** (`marketplace.pricelist` /
`marketplace.pricelist.item`, крок 5): SKU, ціна, залишок по кожній позиції. Помилки
синхронізації фіксуються в полі `sync_error` позиції; поведінка при помилці —
`sync_error_handling`.

> Синхронізація складу/цін наживо потребує реальних ключів (див. «Передумови»).

> _Скриншот:_ `05-sync-stock-prices.png`

## 5. Прайслисти та YML/XML-фіди

### 5.1. Прайслист

**Маркетплейси → Прайслисти.** `marketplace.pricelist` — набір товарів для вивантаження:
генерація позицій, обчислення SKU/ціни/залишку, публікація. Прайслист прив'язується до
бекенду полем `feed_pricelist_id`.

### 5.2. Фід

Фід генерується ядром (`marketplace.backend._generate_feed`, реальний YML-каталог
`yml_catalog → shop → offers` через `lxml.etree`; XML наразі делегує до YML). Публічні
маршрути (`controllers/main.py`):

| Маршрут | Формат |
|---------|--------|
| `/marketplace/feed/<backend_id>` | за замовчуванням бекенду (`feed_format`) |
| `/marketplace/feed/<backend_id>/yml` | YML |
| `/marketplace/feed/<backend_id>/xml` | XML |

Умови віддачі: увімкнено `feed_enabled` (інакше 403), бекенд існує (інакше 404). Якщо
`feed_auth_enabled` — потрібна Basic-авторизація (`feed_auth_login` / `feed_auth_password`,
інакше 401). Готовий URL зручно скопіювати кнопкою **Копіювати URL фіду**
(`action_copy_feed_url`).

Саме цей URL вставляється в кабінеті маркетплейсу/агрегатора як джерело каталогу.
**Фід можна відкрити й перевірити на демо** без зовнішніх ключів.

> _Скриншот:_ `06-feed-yml.png`

## 6. Вебхуки

Приймання подій з маркетплейсу (нове замовлення / оновлення статусу) — маршрут
`/marketplace/webhook/<backend_id>` (тип `jsonrpc`, public). Вмикається прапорцем
`webhook_enabled`; підпис перевіряється за `webhook_secret` (HMAC). URL для реєстрації в
кабінеті маркетплейсу — поле `webhook_url`.

Вебхуки — альтернатива крону імпорту: маркетплейс сам штовхає нове замовлення в Odoo
одразу, без очікування наступного циклу.

> _Скриншот:_ `07-webhook-config.png`

## 7. Крони синхронізації

**Налаштування → Технічне → Заплановані дії** (`data/ir_cron_data.xml`). Усі крони
проходяться по **активних** бекендах:

| Крон | Інтервал | Метод |
|------|----------|-------|
| Marketplace: Import Orders | 15 хв | `_cron_import_orders_all` |
| Marketplace: Sync Stock | 30 хв | `_cron_sync_stock_all` |
| Marketplace: Sync Prices | 1 год | `_cron_sync_prices_all` |
| Marketplace: Refresh API Tokens | 12 год | `_cron_refresh_tokens` |

Індивідуальні інтервали бекенду (`sync_stock_interval`, `sync_prices_interval`,
`import_orders_interval`) дозволяють розріджувати виклики для конкретного підключення.

> _Скриншот:_ `08-crons.png`

## 8. Прайс-агрегатори (Price.ua, Hotline) — лише фід

Модулі `l10n_ua_marketplace_priceua` та `l10n_ua_marketplace_hotline` — тонкі розширення
`marketplace.backend` **без API замовлень/складу**. Створюється бекенд типу `priceua` /
`hotline`, заповнюється `*_merchant_id` (+ опційна категорія фіду), а сам **YML-фід формує
ядро** (крок 5). Дія **Копіювати URL фіду** (`action_copy_feed_url`) дає готове посилання
для кабінету агрегатора. Кроки 3–4 (замовлення, синхронізація складу) для них не
застосовуються.

> _Скриншот:_ `09-priceua-hotline.png`
