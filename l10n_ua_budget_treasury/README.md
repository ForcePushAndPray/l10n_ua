# Ukraine - Budget Treasury (Казначейство)

[![License: LGPL-3](https://img.shields.io/badge/license-LGPL--3-blue.svg)](https://www.gnu.org/licenses/lgpl-3.0-standalone.html)

Інтеграція бюджетного обліку з Державною казначейською службою України (ДКСУ).
Поверх `l10n_ua_budget_estimate`.

## Можливості

* **Довідник органів ДКСУ** — центральний апарат + 26 обласних ГУДКСУ
  (включно з Києвом, Севастополем, АР Крим). З ієрархією для районних УДКСУ.
* **Розширення `account.journal`** — позначка казначейського рахунку,
  тип (реєстраційний / спецреєстраційний / депозитний / поточний валютний),
  прив'язка до територіального органу, КПКВК, фонду.
* **Контроль ліміту асигнувань** при проведенні платежу:
  * Перевіряє кожну (рік × КЕКВ × фонд × КПКВК) комбінацію в проводці.
  * Сумує `debit` всіх рядків з тим же ключем у тій же проводці.
  * Порівнює з затвердженим кошторисом (план − касове виконання).
  * Кидає `UserError` з усіма порушеннями одним зведеним повідомленням.
  * Перевірку можна вимкнути на рівні журналу (`ua_treasury_check_limit`).
* **Wizard імпорту виписки ДКСУ** — CSV-формат за замовчуванням, з точкою
  розширення `_parse_custom()` для реальних форматів (DBF, текстові
  колонкові формати — підключаються через окремі плагіни).

## Залежності

* `account` (стандартний Odoo)
* `l10n_ua_budget_base`
* `l10n_ua_budget_estimate`

## Нормативна база

* **Бюджетний кодекс України ст. 43, 48** — єдиний казначейський рахунок
* **Наказ Мінфіну № 938 від 28.10.2015** — порядок казначейського
  обслуговування державного бюджету за видатками
* **Наказ Мінфіну № 130 від 17.03.2017** — порядок обслуговування доходів
  та інших надходжень

## Як користуватися

1. **Налаштування журналу**: Бухгалтерія → Налаштування → Журнали →
   обрати банківський журнал, що відповідає реєстраційному рахунку,
   увімкнути «Казначейський рахунок», заповнити тип/орган/КПКВК/фонд.
2. **Затверджений кошторис**: створити в `l10n_ua_budget_estimate`,
   затвердити (`approved` або `executed` стан).
3. **Платіж**: створити проводку на казначейському журналі з рядками,
   що мають заповнені КЕКВ + фонд + (опційно) КПКВК. При `action_post()`
   система автоматично перевірить ліміт.
4. **Виписка**: Бюджетний облік → Імпорт виписки ДКСУ → завантажити
   CSV → отримати `account.bank.statement` для подальшої звірки.

## Формат CSV виписки

UTF-8, заголовки в першому рядку. Колонки:
* `date` — YYYY-MM-DD
* `description` — призначення платежу
* `partner_name` — контрагент (опційно)
* `amount` — сума (додатна — надходження, від'ємна — списання). Кома
  або крапка як десятковий роздільник.
* `reference` — посилання/номер документа (опційно)

## Обмеження

* Реальні формати виписок ДКСУ (DBF, текстові колонкові) не реалізовані —
  лише розширювана архітектура з CSV-заглушкою. Конкретні формати треба
  підключати окремими модулями (`l10n_ua_budget_treasury_dbf` тощо).
* Поки що немає інтеграції з механізмом зобов'язань (`account.payment.term`,
  `purchase.order`) — контроль ліміту спрацьовує лише при проведенні
  `account.move`. Зобов'язання, прийняті до оплати, не блокуються.
* Не підтримує депозитні рахунки повноцінно — тільки маркування типу.
